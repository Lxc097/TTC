# 目录说明

这份文档回答两个问题：**每个文件夹是做什么的**、**改某个功能该去哪里**。

仓库按功能组织：一个功能往往同时涉及一个前端目录、一个后端目录和一条访问路由。下面先按功能列，再按目录列。

## 一、按功能找代码

| 功能 | 前端 | 后端 | 访问入口 |
|---|---|---|---|
| 双人面试间：创建房间、加入房间、实时信号、追问提示、面试纪要 | `frontend/interviewer/`（面试官工作台）、`frontend/candidate/`（候选人面试页） | `backend/interviewer/`：`api.py` 房间接口、`ws.py` WebSocket / 信号 / 转写、`shared/engine.py` 判定规则 | `/classic/`、`/personal/`、`/ws/room/{code}` |
| 面试报告与个人复盘 | 两端报告页 | `backend/interviewer/report.py`：面试官「面试质量报告」与候选人「表达回看」 | 面试结束后跳转 |
| 简历投递与申请进度 | `frontend/candidate/`：`apply.html`、`applications.html`、`account.html`、`recruitment.js` | `backend/candidate/recruitment_api.py`、`recruitment_store.py` | `/personal/apply.html`、`/personal/applications.html` |
| 企业岗位与 HR 初筛 | `frontend/interviewer/screening.html` + `screening.js` | `backend/candidate/`：`recruitment_api.py`、`recruitment_resume.py`、`resume_screening_*.py`、`recruitment_evidence.py` | `/classic/screening.html` |
| 招聘阶段推进：阶段映射、真人面试、邀请记录、结果可见性 | `frontend/interviewer/`：`screening.html/js`、`ai-results.html/js`、`human-results.html/js`、`invites.html/js`、`recruitment-core.js`；候选人端 `frontend/candidate/status.html` + `recruitment.js` | `backend/candidate/pipeline.py`、`recruitment_store.py`、`recruitment_api.py` | `/classic/screening.html`、`/classic/ai-results.html`、`/classic/human-results.html`、`/classic/invites.html`、`/personal/status.html` |
| 正式 AI 初面：出题、追问、回答总结 | `ai-interview/`（React 页面） | `backend/candidate/formal_interview_api.py`（鉴权、转发）+ `ai-interview/server/`（Node 侧车） | `/ai-interview/` |
| 账号、登录与权限隔离 | 两端页面 | `backend/candidate/recruitment_api.py`（candidate / hr 两套身份） | `/api/auth/*`、`/api/candidate/*`、`/api/hr/*` |
| 公共基础：配置、内存存储、模型与视觉适配 | — | `backend/shared/` | — |
| 服务入口与静态页面托管 | — | `backend/app.py` | `/`、`/api/config` |

## 二、按目录看职责

### `frontend/` —— 两套纯静态页面（不需要构建）

| 目录 | 面向谁 | 内容 |
|---|---|---|
| `frontend/interviewer/` | 企业 HR、面试官 | `index.html` + `app.js`（面试官工作台，hash 路由）、招聘工作台：`screening.html` + `screening.js`（查看简历 / AI 初筛标准）、`ai-results.html` + `ai-results.js`、`human-results.html` + `human-results.js`、`invites.html` + `invites.js`、`recruitment-core.js`（共享鉴权/接口/导航/弹窗）、`styles.css`、`screening.css`、`workspace.css`、`images/` |
| `frontend/candidate/` | 候选人 | `index.html` + `app.js`（加入房间、面试、个人复盘）、`status.html`（我的状态：只展示当前阶段）、`apply.html`、`applications.html`、`account.html`、`recruitment.js`、`recruitment.css`、`styles.css` |

两套页面都由 `backend/app.py` 直接托管，分别挂在 `/classic/` 与 `/personal/`，接口一律同源调用。

### `backend/` —— FastAPI 服务，按功能分目录

| 目录 / 文件 | 负责的功能 | 关键文件 |
|---|---|---|
| `backend/app.py` | 服务入口：CORS、静态页面挂载、`/api/config`、自测页 | — |
| `backend/interviewer/` | 面试间功能：房间、WebSocket、实时信号、面试报告 | `api.py`、`ws.py`、`report.py` |
| `backend/candidate/` | 招聘功能：账号、岗位、投递、简历解析与初筛、阶段推进、邀请、真人面试、正式 AI 初面闸门、面试后分析 | `recruitment_api.py`、`recruitment_store.py`、`pipeline.py`、`recruitment_resume.py`、`resume_screening_prompt.py`、`resume_screening_service.py`、`recruitment_evidence.py`、`formal_interview_api.py`、`interview_analysis_service.py` |
| `backend/shared/` | 公共基础：配置、信号引擎、内存房间/会话、LLM、ASR、视觉适配 | `config.py`、`engine.py`、`store.py`、`llm.py`、`stt.py`、`vision*.py` |
| `backend/static/` | 后端自测页，不加载前端也能验证接口 | `dev_candidate.html`、`dev_recorder.html` |
| `backend/tests/` | 回归测试（217 个用例，含招聘、招聘阶段管道、正式初面、房间链路） | `test_*.py` |
| `backend/tools/` | 真实接口验证脚本：探针、连通性、端到端 | `verify_keys.py`、`probe_*`、`smoke_*` |

### `ai-interview/` —— 正式 AI 初面应用

- `src/`：React + Vite 页面（面试间、设备检查、报告页）。
- `server/`：本地 Node 侧车，负责出题、追问、回答总结与生物信号，默认只监听 `127.0.0.1:8787`。
- 构建命令 `npm run build:formal` 输出到 `dist/`，由 FastAPI 挂到 `/ai-interview/`；未构建时该路径不存在。

### `deploy/` —— 部署

`setup.sh` 负责建 venv、装依赖、写 `.env`、配置 systemd 与 nginx；`README.md` 是部署说明。nginx 的企业端根目录指向 `frontend/interviewer/`，`/personal/`、`/api/`、`/ws/` 反代到后端。

### `docs/` —— 文档

方案、FacePhys 接入、前端对接、网页端功能梳理、招聘流程与状态机、接入测试指南，以及这份目录说明。

### `legacy/` —— 归档

`legacy/old-root/` 是旧版整仓快照，`legacy/tianjing-practice-personal/` 是历史演示副本。**不参与运行，不要在这里改代码**，只用于对照历史实现。

## 三、请求是怎么分发的

| 路径 | 实际处理者 |
|---|---|
| `/classic/` | `frontend/interviewer/` 静态文件 |
| `/personal/` | `frontend/candidate/` 静态文件 |
| `/ai-interview/` | `ai-interview/dist/`（未构建则不存在） |
| `/ws/room/{code}` | `backend/interviewer/ws.py` |
| `/api/rooms`、`/api/sessions`、`/api/hints` | `backend/interviewer/api.py` |
| `/api/auth/*`、`/api/candidate/*`、`/api/hr/*`、`/api/applications/*` | `backend/candidate/recruitment_api.py` |
| `/api/hr/jobs/{id}/criteria`、`/api/hr/invitations`、`/api/hr/applications/{id}/human-interview*` | `backend/candidate/recruitment_api.py`（阶段判定在 `pipeline.py`） |
| `/api/interview/*`（正式初面） | `backend/candidate/formal_interview_api.py` |
| `/api/config`、`/`、`/recorder` | `backend/app.py` 与 `backend/static/` |

## 四、「我想改 X，去哪」

| 想改的东西 | 改这里 |
|---|---|
| 企业端界面、初筛页、面试间布局 | `frontend/interviewer/`：招聘工作台四页共用 `recruitment-core.js`，样式在 `workspace.css` |
| AI 面试结果 / 真人面试结果 / 邀请记录页 | `frontend/interviewer/ai-results.*`、`human-results.*`、`invites.*` |
| 候选人页面、投递流程、复盘页 | `frontend/candidate/` |
| 候选人「我的状态」阶段页 | `frontend/candidate/status.html` + `recruitment.js` 的 `renderStatus`（阶段判定调用后端 `pipeline` 的返回字段） |
| 房间逻辑、WebSocket、实时信号、提示卡 | `backend/interviewer/` |
| 报告文案与结构 | `backend/interviewer/report.py` |
| 账号 / 岗位 / 投递 / 初筛 / 邀请 | `backend/candidate/recruitment_api.py`、`recruitment_store.py` |
| 阶段怎么分、邀请什么时候算过期、结论文案 | `backend/candidate/pipeline.py`（唯一判定来源，别在页面里另写一套） |
| 真人面试安排 / 结论 / 结果是否发给候选人 | `backend/candidate/recruitment_api.py`、`recruitment_store.py`（表 `human_interviews`） |
| 简历解析、初筛提示词、模型调用 | `backend/candidate/recruitment_resume.py`、`resume_screening_*.py` |
| 正式 AI 初面的出题 / 追问 / 总结 | `ai-interview/`（页面与 Node 侧车）+ `backend/candidate/formal_interview_api.py`（鉴权与转发） |
| 阈值、开关、模型地址 | `backend/shared/config.py` + `backend/.env`（不入库） |
| 部署方式、nginx、systemd | `deploy/` |
| 历史版本对照 | `legacy/`（只读） |

## 五、本地启动（最短路径）

```bash
cd backend
pip install -r requirements.txt
set VISION_PROVIDER=mock
uvicorn app:app --reload --port 8000
```

- 企业端：<http://127.0.0.1:8000/classic/>
- 候选人端：<http://127.0.0.1:8000/personal/>
- 后端自测：<http://127.0.0.1:8000/>
- 正式 AI 初面：在 `ai-interview/` 执行 `npm ci && npm run build:formal`，另开终端 `npm run api:formal`，再访问 `/ai-interview/`
