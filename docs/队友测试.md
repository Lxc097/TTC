# 队友测试通道 · 怎么开、怎么关

> 一句话：**API key 不需要发给任何人。** 这套工程里所有外部调用都在服务端
> （硅基流动、百炼 ASR、DeepSeek、FacePhys），浏览器从头到尾拿不到 key。
> 所以"开放测试"要解决的不是"怎么安全地发 key"，而是"哪台机器持 key、谁拿得到入口"。

---

## 0. 先核对事实（2026-11-14 实测）

| 事实 | 怎么核的 | 结论 |
|---|---|---|
| 仓库里没有 key | `git ls-files` 只有 `.env.example`；`grep -rE 'sk-[A-Za-z0-9]{20,}'` 0 命中 | ✅ key 从未进过 git |
| 浏览器拿不到 key | 前端只有 `fetch('/api/...')`；四个 SDK 全部在 `backend/` 里 import | ✅ 没有前端硬编码 |
| 没有 `.env` 也能起 | 清空 `.env` 直接 `uvicorn app:app`，`/healthz` 返回 `{"vision_provider":"mock","llm_enabled":false}` | ✅ 零 key 可跑 |

**所以"key 不能暴露 → 不能给队友测"这个前提本身就不成立。** 真正卡住的是下面两件事：

1. `RECRUITMENT_DEMO_MODE` 只认 loopback（`candidate/recruitment_api.py` 的 `demo_enabled`），
   所以"把链接发出去"这件事在代码里是被拦住的；
2. 摄像头/麦克风要求**安全上下文**，`http://192.168.x.x:8000` 打开时
   `navigator.mediaDevices` 直接是 `undefined` —— 这个坑仓库里已经踩过一次
   （commit `ef4a454`，`fix(stt): 麦克风失败原因不再一律显示'权限被拒'`）。

## 1. 三种做法，按"省事"排序

### 方式 A · 零 key 本地跑（**默认就该是这个**）

队友什么都不用问你：

```bash
git clone https://github.com/Lxc097/TTC.git && cd TTC/backend
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

**不要建 `.env`。** 不建的时候：`VISION_PROVIDER=mock`、`LLM_ENABLED=0`、
`STT_ENABLED=0`、无 `SILICONFLOW_API_KEY`。

| 能测 | 不能测 |
|---|---|
| 全部页面、路由、WebSocket 握手 | 真实初筛结论 |
| 报告渲染、空态、错误分支 | 真实语音转写 |
| HR 工作台的交互与状态机 | 真实心率 / 双确认触发 |
| 演示模式的完整点击流程 | 硅基流动的真实引用校验 |

页面：`/classic/screening.html`（企业端）、`/personal/account.html`（候选人端）、
`/`（自测台）。覆盖大约 80% 的"这个东西长什么样、点下去会不会崩"。

### 方式 B · 一台机器持 key + 口令 + https 入口（**要真测就用这个**）

那台机器可以是你的笔记本，也可以是服务器。步骤：

1. 只在那台机器上写 `backend/.env`（`chmod 600`），填 `SILICONFLOW_API_KEY` 等；
2. 设一个口令：`TTC_ACCESS_CODE=<自己想一个>`（见第 3 节）；
3. 起服务；
4. 把 8000 变成 **https** 入口，三选一：

   | 做法 | 适合 | 代价 |
   |---|---|---|
   | `cloudflared tunnel --url http://127.0.0.1:8000` | 临时给几个人试 | 国内速度不稳，URL 每次变 |
   | `ssh -R 18000:127.0.0.1:8000 root@你的服务器` + nginx 反代 | 域名证书都在手上 | 需要服务器 SSH |
   | 直接部署到服务器（`deploy/setup.sh`） | 长期挂着 | 改一次代码要重启一次 |

5. 把 `https://...` + 口令 发到群里。

> **必须 https。** 局域网 IP 走 http，摄像头和麦克风直接不可用，
> 队友看到的现象是"点了没反应/权限被拒"，会浪费很多时间去查错。

### 方式 C · 服务器常驻（`deploy/setup.sh`）

脚本已经写好了（nginx + systemd + 可选 certbot），默认 `VISION_PROVIDER=mock`
`LLM_ENABLED=0` —— 也就是**公开也不花钱**。要开真实能力才改 `.env` 里的 key。

⚠️ 当前仓库还有一个更硬的红线：旧 `/api/interviews` 和按 session 查报告的接口
**没有角色鉴权**。所以服务器上开真实 key 之前，先把口令门打开，
否则任何人拿到域名都能读别人场次的报告。

## 2. 为什么"局域网 IP 直连"不行

Web 平台规定，只有 `https://`、`http://localhost`、`http://127.0.0.1` 属于
**安全上下文**。`getUserMedia`（摄像头/麦克风）和 `MediaRecorder` 只在安全上下文里存在。

所以：

```
http://127.0.0.1:8000        ✅ 你自己测没问题
http://192.168.1.23:8000     ❌ navigator.mediaDevices === undefined
https://xxx.trycloudflare.com ✅ 队友能用
https://woaiyrb.com          ✅ 队友能用
```

这也解释了为什么"发个 IP 给队友"这条路一直走不通，不是代码坏了。

## 3. 这次补的代码：共享口令门

新增 `backend/access_gate.py`，在 `app.py` 里接了三行：

```python
if config.ACCESS_CODE:
    app.add_middleware(AccessGate, code=config.ACCESS_CODE, days=config.ACCESS_CODE_DAYS)
```

配置（`backend/.env`）：

```ini
# 留空 = 不设门。本机开发/跑测试就是这个状态，行为完全不变。
TTC_ACCESS_CODE=随便一个你不会忘的口令
# cookie 有效天数；0 = 不过期（靠换口令吊销）
TTC_ACCESS_CODE_DAYS=14
```

它做了什么：

| 行为 | 说明 |
|---|---|
| 默认关闭 | `TTC_ACCESS_CODE` 为空时中间件完全不介入，205 个单测的行为不变 |
| 覆盖 WebSocket | 纯 ASGI 中间件；FastAPI 的 `@app.middleware("http")` 看不到 `/ws/room/{code}` |
| 换口令即吊销 | cookie 用口令本身派生 HMAC 签名，改 `.env` 重启后旧 cookie 全部失效 |
| 放行必要路径 | `/healthz`、`/.well-known/`（ACME）、CORS 预检 `OPTIONS` |
| 登录页 | 未登录的页面请求返回一个自带样式的口令页，输完 303 跳回原地址 |
| 挡开放重定向 | `next` 只接受站内绝对路径，`//evil.com` 会被改回 `/` |

已实测（13 项断言全过）：未登录 401、错误口令 401、正确口令 303 + HttpOnly cookie、
登录后 `/api/*` 200、伪造 cookie 401、未登录 WS 被拒、`//evil.com` 被挡回 `/`。

**它不是账号体系。** 拿到口令的人在企業端就是 HR 视角。要分人得另做邀请码/账号。

## 4. 一个必须知道的真相：loopback 判断不是安全边界

`demo_enabled()` 原来的判据是「客户端 IP 是 loopback」。这个判断

```
一旦前面挂了 nginx / cloudflared / frp / ssh -R，
远端用户连过来时 request.client.host 也是 127.0.0.1
```

也就是说：**只要加了反代，「开给队友」和「开给全网」在原代码眼里没有区别。**
所以口令不是锦上添花，是必需品。

现在 `demo_enabled()` 接受两个判据：loopback **或** 口令已验证。
这样即使哪天忘了设口令、又挂了反代，行为也和以前一致（不会更糟）；
但只要设了口令，它就按口令走。

## 5. 成本闸：开给多人之前必须想清楚

| 能力 | 单价 | 现在的闸 | 缺口 |
|---|---|---|---|
| FacePhys 取证 | ~17 万 token / 20 秒片段；115 万余额 ≈ **6 段** | 每场最多 5 段（`CONFIRM_MAX`）、余额低于 `TOKEN_FLOOR` 停手 | **没有跨房间的全局闸** |
| 硅基流动初筛 | 便宜 | 无 | 可被刷 |
| 百炼 ASR | 便宜 | 无 | 可被刷 |

建议：

```ini
# 多人测试期：生理数据一律用假曲线，不碰 FacePhys
VISION_PROVIDER=mock
# 真要验一次真心率：临时改回 facephys，验完立刻改回并重启
CONFIRM_MAX=1
```

`VISION_PROVIDER` 是进程启动时读的，**改完必须重启**。

## 6. 怎么关

| 想要的效果 | 做法 |
|---|---|
| 只踢掉所有人、保留服务 | 换 `TTC_ACCESS_CODE` 的值并重启；旧 cookie 立刻全部失效 |
| 立刻断掉外部入口 | 杀掉隧道进程（cloudflared / ssh -R）；服务本身还在本机 |
| 彻底停掉 | `Ctrl+C` 停 uvicorn；服务器上 `systemctl stop ttc-backend` |
| 收回某一个人的权限 | 做不了 —— 口令是共享的。要分人就得每人一个码（下一版） |
