# 网页端功能梳理 · 耳语 / 彩排

> TTC 黑客松 · 前端功能规格 v1
> 前提：一个代码库、一套组件、两个主题（`?role=interviewer|candidate`）

---

## 0. 三个结构性判断（先定这三条，其余都是细节）

### ① AI 在「耳语」里闭嘴，在「彩排」里开口

| | 耳语（面试官侧） | 彩排（候选人侧） |
|---|---|---|
| AI 角色 | **静音旁观** | **出声提问** |
| 谁主导 | 人类面试官 | AI 面试官 |
| 语音接口用法 | 只用 STT（听）+ 行为特征 | 全链路 STT + LLM + TTS |
| 屏幕归谁 | 面试官 | 候选人本人 |
| 视觉主题 | 深色 · 专业 | 浅色 · 友好 |

**为什么这个划分是对的**：它让"什么是双边"变成一句能讲的话——*同一个引擎，AI 在一侧闭嘴、在另一侧开口*。同时候选人侧天然是一个**可以独立演示**的完整产品（对应题目第二条「AI 电话沟通」），不怕现场没人配合。

### ② 同一个页面，`role` 决定三件事

一个 `role` 参数切换：**主题色 / 提示卡文案来源 / AI 是否出声**。组件树完全复用，只换展示层与数据源。**绝不写两套 UI**（UI 是 48 小时最大的隐形黑洞）。

### ③ 界面必须"沉默"

面试官在候选人说话时不该低头看屏幕。所以主视觉不是数字、不是图表，是一条**只有颜色、没有数字**的 4px 细带（见 §4.2）。数字一旦上屏，人就忍不住去读，产品就变成了仪表盘。

## 1. 路由与页面清单

| 路由 | 页面 | 角色 | 优先级 | 说明 |
|---|---|---|---|---|
| `/` | 落地/起始 | 通用 | P0 | 两个入口大按钮 + 一次性设备自检 |

## 2. 页面 1：起始页 `/`

**唯一目的：让面试官在 30 秒内开始一场能被信任的面试。**

| 功能 | 说明 | 优先级 |
|---|---|---|
| 两个入口 | 「我要面试人」(深色卡) / 「我要练一练」(浅色卡) | P0 |
| 职位与题目模板 | 输入职位名 + 选 3 道题（预置 5 个模板即可，别做编辑器） | P1 |
| 设备自检 | 见下 | **P0** |
| 授权状态确认 | 「本次已获得候选人同意」勾选框 → 勾了才让进 | P1 |

### 2.1 设备自检（这是全项目性价比最高的一个小功能）

三个指标，全部当场出结果，不合格不允许开始：

```
● 人脸检出      已检测到 1 张人脸
● 光照          充足（建议避免逆光）
● 信号质量      82%  ── 可以开始
```

- 信号质量直接取 API 返回的 `quality` 字段。
- **质量低时要说实话**：「信号质量 41%，本次生理数据不可靠，建议调整位置或改用纯行为模式」+ 一个「仍然开始（仅行为信号）」按钮。

> 为什么值得做：它把一个"我凭什么信你"的问题，在开场前就回答了。而且 Demo 现场如果信号差，它可以当挡箭牌——**系统自己说了不可靠**。

## 3. 页面 2：面试进行中 `/live`（P0，核心）

### 3.1 线框

```
┌───────────────────────────────────────────────┬──────────────────┐
│                                               │  提示区 (280px)  │
│           候选人视频（大画面）                 │  ┌────────────┐  │
│           右上角：● 录音中 03:41               │  │ ⚠ 追问      │  │
│                                               │  │ 具体卡在哪  │  │
│                                               │  └────────────┘  │
│                                               │   (最多 2 张)    │
├───────────────────────────────────────────────┤                  │
│ 实时字幕：…后来因为公司战略调整，就没上线…     │  ── 轮次 03 ──   │
├───────────────────────────────────────────────┤  已采纳 2 / 忽略 1│
│ ▁▁▂▂▂▃▃▄▄▄▄▃▃▂▂▁▁▁▁  ← 4px 信号带，无数字     │                  │
└───────────────────────────────────────────────┴──────────────────┘
```

### 3.2 功能点

| # | 功能 | 关键规格 | 优先级 |
|---|---|---|---|
| 1 | 视频预览 | `getUserMedia`，本地预览不落盘；右上角计时 + 录音指示 | **P0** |
| 2 | 抽帧上报 | 5fps、降采样到 320px 宽、JPEG 0.6，走 WebSocket | **P0** |
| 3 | 实时字幕 | STT 流式增量渲染，只保留最近 2 行，超过 4 秒淡出 | **P0** |
| 4 | **信号带** | 4px 高、贴底、按 `load_z` 上色，**永不出现数字** | **P0** |
| 5 | 追问提示卡 | 右侧滑入，≤10 字，3 秒后自动折叠成图标 | **P0** |
| 6 | 提示展开 | 点开显示「为什么」一句话 + 「用掉/忽略」 | P1 |
| 7 | 反馈计数 | 「已采纳 2 · 忽略 1」直接上屏（见 §5） | P1 |
| 8 | 轮次分隔 | 检测到停顿 > 1.5s 时插入轮次标记 | P1 |
| 9 | 结束按钮 | → 生成报告，转场时显示「正在整理 3 个追问点…」 | **P0** |
| 10 | 隐私提示 | 左下角小字「画面仅本地处理，面试结束即删」 | P1 |

### 3.3 信号带规格（本项目的视觉签名）

| `load_z` | 颜色 | 行为 |
|---|---|---|
| < 0.8σ | `#2a2a2e` 灰 | 静止，几乎看不见 |
| 0.8–1.5σ | `#3b6ea5` 蓝 | 轻微起伏 |
| 1.5–2.0σ | `#c08a3e` 琥珀 | **开始有呼吸感动效** |
| > 2.0σ 且行为异常 | `#b3453e` 红 | 同时弹出提示卡 |
| API 降级 | 灰 + 斜条纹 | 表示「这一路信号不可用」 |

- 用 Canvas 或一个 `div` 宽度 + `linear-gradient` 即可，**不要引入图表库**。
- 单一信号不足阈值时**绝不出提示**——色带可以动，卡不能弹。

### 3.4 提示卡文案规格

- **正文 ≤ 10 个字**，动词开头，能直接照着问。
- 三种类型：`probe`（追问）/ `upgrade`（加难度）/ `wrap`（收）
- 卡片只给"问什么"，不给"结论"。

```
✓ 追问：具体卡在哪        ✗ 候选人在隐瞒（结论，禁止）
✓ 升级难度：问数据量      ✗ 该候选人技术深度不足（评价，禁止）
✓ 收：换轻松话题          ✗ 候选人已疲劳，建议淘汰（决策，禁止）
```

> 这个"三禁止"写进设计规范，是答辩时最容易被记住的一页。

## 4. 页面 3：彩排 `/rehearsal`（P1）

AI 出声提问，回合制。**产品目的是拿授权，所以体验必须比真实面试更舒服。**

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| 1 | 题目卡片 | 3 道预置题，可换一批；不做自定义 | P1 |
| 2 | AI 出声提问 | TTS 播报 + 字幕同步；支持打断（VAD） | P1 |
| 3 | 回合建议卡 | 每答完一题，立刻给 1 条建议（不是 3 条，会看不过来） | P1 |
| 4 | **必须有 1 条亮点** | 每轮至少一条正面反馈，否则没人敢用第二次 | P1 |
| 5 | 自己的曲线 | 回合结束后展示这一题的 `load_z` sparkline | P2 |
| 6 | 结束 → 报告 | 复用同一报告组件 | P1 |

### 建议卡文案样例（这是产品灵魂，抄这几个句式）

```
▸ 语速 235 字/分，几乎没有停顿。面试官想追问也插不进嘴——留白比多说有力。
▸ 第 3 题之后句长掉了 40%、呼吸变浅。这是你的注意力拐点：
  真实面试前 25 分钟决定印象，把最想讲的放前面。
▸ 这题负荷比你自己基线高 2.1 个标准差，但内容质量是全场最高的——
  不是你不懂，是这段还没练熟。再讲两遍就顺了。
✦ 亮点：你讲技术选型时语速最稳、停顿最少，这段可以当模板。
```

**硬规则：不出现分数、排名、百分比评级、任何"你在第几名"。**

## 5. 反馈闭环：为什么「已采纳 2 · 忽略 1」要上屏

这是整个前端里唯一一个**产品指标驱动技术指标**的设计。

- 面试官点「用掉」→ 记正样本；点「忽略」→ 记负样本。
- 报告顶部显示：**「本场 5 条提示，采纳 4 条（80%）」**。
- 答辩时用这个数字代替准确率：

> 「我不给你实验室准确率，我给你**面试官采纳率**。采纳率低，说明提示没用，准确率再高也没意义。」

一个能把"正确"翻译成"有用"的指标，比任何 benchmark 都更能说服评委。

## 6. 同意模态（P1，但强烈建议做）

候选人在第一次进入前弹出，**不占路由**。三行说明 + 两种授权粒度：

```
我们会采集：摄像头画面中的面部信号、说话声音
只用来做：本次的追问建议（不评分、不排名、不进入任何档案）
你随时可以：暂停、删除、改用纯语音

  [ 授权本场（视频 + 语音） ]   [ 只用语音，不采集画面 ]
  □ 我理解这不是一次心理评估
```

- **「只用语音」这个降级按钮必须做**——它是"我们真的尊重选择"的唯一证明，评委看这一眼就知道团队想清楚了。
- 候选人侧（彩排）额外一句：「这份报告只属于你，可以导出，也可以一键删除」。

## 7. 异常与降级态（P0，现场能不能演完全靠它）

| 场景 | UI 表现 |
|---|---|
| 视频 API 超时 | 顶部黄条「生理信号暂停，行为信号仍可用」+ 信号带变灰条纹 |
| WebSocket 断开 | 顶部红条「连接中断，正在重连…」，本地缓存帧，不清空画面 |
| 摄像头权限拒绝 | 全屏引导 + 「仅语音模式」按钮 |
| 浏览器不支持 | 检测 `getUserMedia`，引导用 Chrome |
| 无人在画面 | 视频区覆盖「未检测到人脸」遮罩，信号带归零 |
| 报告生成失败 | 降级成「原始记录列表」（时间戳 + 字幕），别给空白页 |

> **每一个降级态都是 demo 现场可能真的遇到的**。宁可少做一个功能，也要把这 6 个状态画完。

## 8. 页面 4：报告 `/report/:id`（P0）

同一个组件，`role` 决定标题与措辞：

| | 面试官版 | 候选人版 |
|---|---|---|
| 标题 | 面试质量报告 | 这次彩排的 3 个收获 |
| 语气 | 客观、给建议 | 具体、给人底气 |
| 数据范围 | 只给时间戳 + 建议 | 给完整曲线 |

```
面试质量报告 · 45 分钟 · 采纳 4/5
────────────────────────────────────
本场有 3 个点值得二面追问：

  02:10  ⚠ 失败项目未说清原因
         负荷 +2.1σ，出现回避性表述  → [回看 20 秒]
  08:45  ⚠ 技术方案深度仅到第一层
         追问后负荷骤降（未触底）      → [回看 20 秒]
  15:20  ○ 候选人明显疲劳，后 2 题信息量低
         建议拆成两轮面试             → [回看 20 秒]

────────────────────────────────────
本报告不包含对候选人的任何评分或排序。
画面仅本地处理，已于 XX:XX 删除。          [复制文本]
```

| # | 功能 | 优先级 |
|---|---|---|
| 1 | 一句话结论 + 3 个追问点卡 | **P0** |
| 2 | 时间戳跳转（回看片段，播放 20 秒） | P1 |
| 3 | 每条显示证据链：负荷 z 值 + 行为特征 | P1 |
| 4 | 采纳率 | P1 |
| 5 | 合规声明 + 删除状态 | **P0** |
| 6 | 复制文本（不做 PDF） | P1 |
| 7 | 完整 `load_z` 曲线 | P2 |

## 9. WebSocket 协议（前后端唯一契约，先定这个再写代码）

```jsonc
// client → server
{"type":"frame",   "t":12.34, "img":"data:image/jpeg;base64,…", "w":320}
{"type":"audio",   "t":12.34, "chunk":"…"}                  // 面试官侧仅 STT
{"type":"turn_end","turn_id":3, "t":42.1}
{"type":"hint_feedback","hint_id":"h_7","action":"used|ignored"}
{"type":"ping"}

// server → client
{"type":"signal",  "t":12.5, "load_z":0.4, "hr":78, "quality":0.82, "face_count":1}
{"type":"hint",    "id":"h_7", "turn_id":3, "kind":"probe|upgrade|wrap",
                   "text":"追问：具体卡在哪",
                   "why":"负荷 +2.1σ，且出现回避性表述", "ts":42.3}
{"type":"transcript","turn_id":3, "text":"…", "final":true}
{"type":"status",  "state":"ok|degraded", "reason":"video_api_timeout"}
{"type":"report_ready","report_id":"r_1"}
```

**约定两条，能省掉后期 80% 的联调痛苦：**

1. 所有消息带 `t`（毫秒级相对时间），前端只按 `t` 对齐，不按本地时钟。
2. `hint` 必须带 `why`——前端不自己编理由，界面上那句"为什么"永远来自后端证据。

## 10. 组件树（复用边界）

```
<App role={interviewer|candidate}>
  ├─ <DeviceCheck/>                 P0  仅在 / 页
  ├─ <ConsentModal/>                P1
  ├─ <SessionShell>                 P0  ← 完全复用
  │   ├─ <StagePane/>               P0  视频 + 字幕 + 计时
  │   ├─ <SignalBand/>              P0  role 只影响可见度，不影响数据
  │   └─ <HintRail role/>           P0  ← 唯一真正的差异化点
  ├─ <RehearsalFlow/>               P1  仅 candidate
  ├─ <ReportView role/>             P0  两套文案
  └─ <DegradedBanner/>              P0  全局
```

**只有 `<HintRail>` 和 `<ReportView>` 的文案是分叉的。** 其余全部共用——这是"15% 成本拿到双边"的实现方式。

## 11. 视觉方向（成本极低，Demo 效果差别很大）

| | 耳语 | 彩排 |
|---|---|---|
| 底色 | `#111214` 深色 | `#faf8f5` 暖白 |
| 主色 | `#3b6ea5` 冷蓝 | `#c9772f` 暖橙 |
| 字体 | 系统无衬线，紧凑 | 系统无衬线，宽松 |
| 气质 | 控制台 | 健身 App |

用 CSS 变量 + `[data-role]` 切换，**10 行代码，Demo 里 20 秒切过去就是两个产品**。

---

## 12. 明确不做的 UI（这三样会让项目直接做死）

1. ❌ **数据看板 / 仪表盘**——一旦有一堆图表，产品就变成了监控。
2. ❌ **候选人排名列表 / 对比视图**——排名的下一步一定是自动淘汰。
3. ❌ **任何形式的评分卡**——包括看起来无害的「竞争力雷达图」。

## 13. 开发顺序（照着写就行）

| 轮次 | 目标 | 产出 |
|---|---|---|
| 1 | 相机 → 帧 → WS → 后端回一个假 `load_z` | 信号带能动 |
| 2 | 真 STT 字幕流 | 字幕能滚 |
| 3 | 真 API 接进来 + 双确认规则 | 能出第一条真提示 |
| 4 | 报告页（先用假数据） | 端到端能演一遍 |
| 5 | 降级态 6 个 | 抗现场 |
| 6 | role 切换 + 主题 | 20 秒第二幕 |
| 7 | 同意模态 | 合规页能演 |
| 8 | 彩排流程 | 时间够才做 |

**在第 4 轮结束前不要碰任何动画和视觉细节。**
