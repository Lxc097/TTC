# TTC · 企业面试双端

> 面试官获得追问提示；候选人回看自己的实际发言与表达建议。两端都不输出候选人评分或排名。

## 这是什么

| | 企业端（面试官） | 个人端（真实面试候选人） |
|---|---|---|
| 入口 | `/classic/`（本地）或站点根路径（部署后） | `/personal/` |
| 输出 | 实时追问提示与面试质量报告 | 本场纪要、本人发言摘录与表达建议 |
| 不输出 | 候选人评分、排名、淘汰建议 | 录用判断、表现分、面试官内部提示 |

`gerenduan/` 是另一套模拟面试原型，与这里的真实面试个人端不同。

## 目录

```
TTC/
├── qiyeduan/          企业端（面试官侧）
│   ├── backend/       FastAPI 后端，已跑通全链路
│   └── docs/          双边方案与网页端功能梳理
├── frontend/          企业端网页（面试官）
├── personal/          本项目的真实面试候选人端（独立页面）
├── gerenduan/         既有模拟面试原型；不参与本次真实面试对接
├── README.md
└── .gitignore
```

## 快速开始

```bash
cd qiyeduan/backend
pip install -r requirements.txt
set VISION_PROVIDER=mock
uvicorn main:app --reload --port 8000
```

打开 <http://127.0.0.1:8000/classic/> 是企业端，创建房间后复制候选人链接；
候选人在 <http://127.0.0.1:8000/personal/> 输入房间号，或直接打开邀请链接。
候选人主动开启摄像头后，面试官端中间大屏会实时显示其画面（仅转发最新帧，不录制、不落盘）。
<http://127.0.0.1:8000/> 仍是后端自测台。两端在本地同源，模拟面试原型不参与这条流程。
候选人报告只依据本场真实转写，提供可追溯的表达建议，不展示面试官内部提示或候选人分数。
本机密钥放在 `qiyeduan/backend/.env`（已被 Git 忽略），默认 `VISION_PROVIDER=mock` 可避免调试时触发付费画面分析。

> 当前仍是本地联调版本：旧企业端场次列表和按会话 ID 查询的报告接口尚无角色鉴权。
> 独立候选人页面只调用候选人报告接口，但服务端权限隔离仍需补齐，勿直接用真实候选人数据公开部署。
细节见 [qiyeduan/backend/README.md](qiyeduan/backend/README.md)。

## 三条不能破的规则

1. 不做情绪标签，只估计认知负荷的相对变化。
2. 生理 ∧ 行为双确认才出提示，单一信号一律静默。
3. 不产生任何自动决策，也不出候选人评分。
